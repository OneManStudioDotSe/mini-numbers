# Mini Numbers — Audit of the working base (2026-11-02)

Scope: authentication, security, user persistence, user-facing functionality and the core
collection → dashboard path, at commit `a4b11da` (v1.3.0, unreleased changes included). Method:
three independent code reads, every claim re-checked in the source, then the C and H items
reproduced against the real fat JAR (`build/libs/mini-numbers-all.jar`) on a throwaway SQLite
database, with `curl`, `sqlite3` and a Chrome session driven by Playwright. Nothing below is
inferred from reading alone unless the row says so.

Severity: **C** broken core flow or auth bypass · **H** wrong result or security hole with real
exposure · **M** works but misleading or fragile · **L** cosmetic or housekeeping.

## Summary

The test suite is green but the base is not yet solid. Two core flows are broken: anyone who knows
a username can forge the admin session, and the "create project" dialog hands out a tracking key
the server never stored. About a hundred test checks pass silently when login fails. The rest of
the product (collection, privacy modes, hashing, reports, goals, funnels, segments, widgets, JWT,
rate limits, role checks, the tracker) works as documented.

## Confirmed working

Login, logout and the 5-attempt lockout; bcrypt verification including legacy `$2a$10` and `$2y$`
hashes; rate limits on the auth endpoints and the admin API; the Origin guard; role re-resolution
on every request, so demotion and deletion apply at once; JWT issue, refresh and rotation; viewers
see a masked API key and get 403 on every mutation; `/collect` validation and all three privacy
modes; visitor hashing with rotation; the tracker (page views, SPA navigation, custom events,
heartbeats, offline queue, outbound links and downloads; `tracker.min.js` matches `tracker.js`);
goals, funnels and segments CRUD and analysis; demo data; raw-event paging; widgets with key
authentication; the `/collect` → dashboard path **when the key is read from the project list or
the API**, which is why C2 went unnoticed; CI on SQLite and PostgreSQL; the Docker image; the
accessibility scans in both themes.

## Order of work

1. Make the tests honest (H1), so a green run means something.
2. Fix C2 (server returns the key; the dialog uses it).
3. Sign the session cookie and resolve the signing key and JWT verifier lazily (C1, C3).
4. Escaping (H2), delete cascade (H3), dead dashboard elements (H4), export (H5).
5. The M items, one per minor release, tracked in [ROADMAP.md](ROADMAP.md).

Feature comparison matrix

Where Mini Numbers wins

  • Deployment weight. One MIT-licensed JAR on SQLite, with funnels, segments, revenue attribution, webhooks and email reports included. Only GoatCounter and Vince come close, and both stop at page views.
  • Privacy you can configure. Cookieless salted hashing with a rotation window from one hour to a year, and three modes whose stored fields are verified by tests.
  • Visualisation taste. Contribution calendar, activity heatmap, globe, one design system in both themes.
  • The JVM. The only analytics server a Kotlin or Java team can run inside the stack they already operate.

Where the field wins

  • Breadth. Umami, Rybbit and PostHog ship replay, heatmaps, web vitals, journeys, retention and agent access.
  • Table stakes added in 2026. User journeys, annotations, retention and bot filtering beyond the User-Agent are now expected and still missing here.
  • Community. Umami at ~39k stars, Plausible ~29k, Rybbit ~13k. Mini Numbers has no release yet.
  • Cloud. Every competitor except GoatCounter offers hosting. Mini Numbers is self-host only, by design.

What changed in the market, 2025–26

  • The AI-assistant referrer channel went from nowhere to everywhere in five months: Matomo in March, GA4 in May, Plausible in June, PostHog in July, Fathom in October 2026. Mini Numbers added it in 1.3.0.
  • Read-only agent access through MCP became the new API surface (Umami, Rybbit, PostHog, Vercel, Fathom, Databuddy).
  • Self-host stacks got heavier. Rybbit, Databuddy and Swetrix all require ClickHouse plus PostgreSQL and Redis.
  • Fathom raised prices twice; Vercel cut web-analytics pricing by up to 80%; newcomers undercut at $6 to $13 a month.

Not in the race, by choice

  • Session replay and heatmaps. The simple-privacy segment (Plausible, Fathom, Simple, Pirsch, Seline) skips them too; they sit badly with a no-identifier promise.
  • Feature flags and A/B testing. Product-analytics territory (PostHog, Swetrix).
  • Hosted plan. The pitch is "run it anywhere, even a Raspberry Pi", not a subscription.

Privacy by design

  • Three modes. Standard keeps country, city, browser, OS and device. Strict keeps country only. Paranoid keeps nothing but the page path and a rotating hash.
  • No cookies, no persistent identifier. The visitor hash is salted and rotates every 24 hours by default, configurable from one hour to one year.
  • No PII. The IP address is used in memory for the hash and discarded; the raw User-Agent is never stored.
  • Privacy posture chip 1.3.0 in the dashboard says in plain words what is stored, what never is, and when it is forgotten.
  • Retention policy deletes events older than N days automatically, with a preview of the impact first.

Dashboard

  • Overview with page views, unique visitors, sessions, bounce rate, session duration, conversion rate and AI assistant referrals 1.3.0, each against the previous period.
  • Time patterns: hourly and daily activity heatmap, 365-day contribution calendar, busiest day, peak hour and top month.
  • Content: top, entry and exit pages, scroll depth, outbound links and file downloads.
  • Audience: countries with city drill-down and an interactive globe; browsers, operating systems and devices.
  • Traffic sources: referrers and UTM source, medium and campaign breakdowns.
  • Real time: live feed and active-visitor counter. Raw events viewer with filters and pagination. Light and dark themes.

Conversion and growth

  • Goals on URL arrivals or custom events, with conversion rates.
  • Funnels with drop-off at each step.
  • Segments built with a visual AND/OR filter builder and analysed in isolation.
  • Revenue attached to any custom event: totals, transactions, average order value, revenue per visitor, breakdown by event, attribution by referrer and campaign.
  • Custom events with properties through MiniNumbers.track(name, props).

Tracker

  • 1.9 KB gzipped, no cookies, no build step: one script tag.
  • Automatic page views, SPA navigation through the History API, heartbeats that pause in hidden tabs, scroll depth, outbound links and downloads.
  • Offline queue that holds events while the browser is offline and drains them on reconnect.
  • Works with sendBeacon as browsers send it; verified end to end in a real browser since 1.3.0.

Integration

  • Webhooks with HMAC-SHA256 signatures, three retries with backoff, a delivery log and test sends, for goal conversions and traffic spikes.
  • Email reports daily, weekly or monthly over SMTP, with selectable sections and custom header and footer.
  • REST API with session or JWT auth and a full OpenAPI 3 spec; embeddable widgets for realtime, page views, top pages and a sparkline, authenticated by a public key.
  • Roles: admin and viewer, with API keys masked for viewers and role changes effective on the next request.

Running it

  • One fat JAR or a small Docker image; SQLite by default, PostgreSQL when you want it.
  • Setup wizard that configures the server without a restart; demo data in one click.
  • Health and metrics endpoints, API key rotation, rate limits on collection, admin and auth, origin allowlist for the admin API.
  • Kotlin and Ktor on JDK 21; MIT licence.

Version 1.3.0 is the October 2026 revival: the first release where every gate is green and the tracker is proven in a real browser. The numbers it shows will be lower than before, and they are the correct ones.

Fixed

  • The tracker could not run in any browser. The script was served without a content type and the server's nosniff header made browsers refuse it. Sites embedding the snippet collected nothing.
  • Every beacon was rejected. sendBeacon posts as text/plain, which the collect endpoint did not accept. It decodes the body directly now, whatever the content type.
  • The offline queue never engaged because sendBeacon reports success even without a network. The tracker now queues while offline and drains on reconnect.
  • Page views were every event. Heartbeats, custom, scroll, outbound and download events were counted as page views across the dashboard. View metrics count page views only; sessions and bounce still use every event.
  • Tests were not testing. The integration suite had been silently skipping every authenticated request. It runs for real now, on SQLite and PostgreSQL, with a browser suite beside it.
  • Origin allowlist and rate limits on the admin and auth endpoints are enforced; role changes and deletions apply on the next request; dialogs carry correct ARIA; the version is reported consistently.

Added

  • AI assistant referrals card: visits referred by ChatGPT, Claude, Perplexity, Gemini, Copilot and eight more, with share of referred traffic and period comparison. Computed from stored referrers, so history is covered.
  • Privacy posture chip and dialog explaining what the instance stores, never stores, and when it forgets.
  • PostgreSQL CI job, Playwright browser suite, Dependabot, issue templates, README screenshots.

Changed

  • Kotlin 2.4, Ktor 3.6, Gradle 9.8, Exposed 1.5, HikariCP 7; the LGPL User-Agent library replaced by an Apache-licensed one; jBCrypt replaced by password4j, which also accepts htpasswd hashes.
  • Browser, OS and device labels read Chrome 120, macOS, Desktop; the tracker size claim is the measured 1.9 KB gzipped.

Still open before launch
